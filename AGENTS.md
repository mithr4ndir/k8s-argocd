# Agent instructions: k8s-argocd

## Purpose

GitOps configuration for the QuasarLab Kubernetes cluster. Helm charts are pre-rendered to
manifests and committed, then ArgoCD reconciles the cluster against this repo. Pushing to
`main` is a deployment.

## Boundaries

- **`environments/dev` owns every live resource.** The `environments-applicationset`
  auto-discovers `environments/*`, but `environments/prod/kustomizatiom.yaml` is 0 bytes
  and the filename is misspelled, so the `prod` Application manages nothing. Its green
  "Synced" status asserts nothing at all. Edit `environments/dev`.
- Sync policy is automated with `prune: true` and `selfHeal: true`. Removing a resource
  from the tree deletes it from the cluster, and manual `kubectl` changes are reverted.
  That is why *arr apps are scaled 0 to 1 through git rather than restarted by hand.
- `environments/dev/kustomization.yaml` currently pulls in
  `infrastructure/{metallb,nfs,monitoring,external-secrets,reloader,security}` and
  `apps/{media,dashboard,science,automation}`.
- Rendered manifests (`common.yaml`, `deployment.yaml`, `service.yaml` and friends under
  `apps/media/*`) are generated by `make` from `values.yaml` and carry Helm's
  `# Source: ...` provenance header. Edit `values.yaml` and re-render. Exceptions that are
  hand-maintained: `apps/media/jellyfin/encoding-configmap.yaml` and all of
  `apps/media/qbittorrent/`, which has no makefile.
- Some components live elsewhere. The lab-scout CronJob is defined here but its image is
  built in the `lab-scout` repo, and palantir-nq's CI renders charts into
  `apps/automation/` and auto-merges the PR.

## Validation

CI covers exactly one component. `.github/workflows/build-discord-alert-proxy.yml` builds
and Trivy-scans the discord-alert-proxy image and fails on HIGH or CRITICAL. Nothing else
in this repo is validated by CI: no Helm render, no kustomize build, no YAML lint. The two
test directories under `apps/science/` and `infrastructure/monitoring/` are run by nothing.

Locally:

```
make all                        # in a component dir: re-render from values.yaml
kubectl kustomize environments/dev   # local render of the root graph, no cluster contact
```

`kubectl kustomize environments/dev` validates the local resource graph only. It does not
validate remote charts, CRDs, or nested ArgoCD Applications, so render and check each
changed child Application separately as well.

## Landmines

- Distinguish desired config from observed health. Ready pods are not a working feature.
- The homepage `siteMonitor` runs inside the pod and rejects self-signed certs, so that dot
  stays red permanently. Do not "fix" it with `NODE_TLS_REJECT_UNAUTHORIZED=0`.
- Never `rollout restart` an *arr app. SQLite on NFS corrupts. Scale 0 to 1 via git.
- `apps/automation/claude-bridge` still exists on disk with its ExternalSecret,
  NetworkPolicy, PDB and PrometheusRules, but is commented out of
  `apps/automation/kustomization.yaml` and the project was retired on 2026-09-14. Do not
  re-enable it without reading that comment.
- Monitoring is Loki plus Vector, not Elastic. Any reference to filebeat is a leftover.
- After changing a 1Password item, kick the ESO sync manually. The refresh interval is 24h.
- Two control-plane VMs (k8cluster2, k8cluster3) sit on the same Proxmox host, pve2, so
  rebooting it loses etcd quorum. Verify placement against live Proxmox before maintenance
  rather than trusting an old inventory. etcd disks are node-local, so these are not clean
  live migrations.

## Forbidden

- Do not `kubectl apply`, `delete`, `scale`, or `patch` against the cluster. Change git.
- Do not dump Secret values or resolved ExternalSecret credentials.
- Do not push a deployable change without authority for that specific task.
- Respect the 1Password quota protections; do not bypass the wrapper or killswitch.

## Completion

A reviewed diff, the render and validation output for each changed Application, and an
explicit statement of what was not verified. For an authorised deployment, verify the
user-visible outcome, not that pods are Ready. Leave unrelated working-tree changes alone.
